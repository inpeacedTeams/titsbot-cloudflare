# Эксплуатация, безопасность и ограничения

## Гарантии и границы

- PostgreSQL — единственный источник истины о попытках и результатах. Все изменения группы выполняются в транзакции с `pg_advisory_xact_lock(chat_id)`.
- `request_id`, `(attempt_id, seq)` и `update_id` защищают от повторной обработки. Конфликтующий пакет событий отвергается. Некорректный live-пакет завершает попытку с нулём; ошибка возвращается после COMMIT, а не откатывает расход попытки.
- Очередь имеет lease 120 секунд, retry/backoff до часа. Срок внешних запросов ограничен. Alarms и минутный Cron восстанавливают обработку после остановок.
- Telegram `sendMessage` не имеет idempotency key. При сбое между отправкой и записью подтверждения возможно дублирующее сообщение (в том числе GO). Бот не обещает exactly-once внешнюю доставку. Результаты БД при этом не дублируются. Для запуска authoritative GO — сообщение, записанное в `chat_tests.go_message_id`.
- Cloudflare alarms и Cron не гарантируют точность до миллисекунды. Дедлайны определяются серверным временем; поздняя обработка не продлевает MT. Результаты Chat могут прийти позже 65 секунд из-за LLM/очереди.
- Webhook подтверждается только после записи данных. Сообщения, дошедшие ПОСЛЕ заморозки Chat Test, уже не попадают в результат. При длительной недоступности webhook возможна неполнота Chat Test; дополнительная попытка автоматически не выдаётся. Проверяйте инфраструктуру ДО калибровки реальных участников.
- Во время недоступности БД приём API возвращает 503, а не принимает события в ненадёжную память. Если outage пересечёт MT-дедлайн, попытка истечёт с нулём — это строгое правило исходного продукта.
- Браузерный античит не доказывает, что печатал человек: продвинутый клиент может синтезировать события с подходящим временем. Не используйте D для решений с серьёзными последствиями.
- Администратор/владелец PostgreSQL технически может изменить схему и снять триггеры. «Неизменяемость» обеспечивается относительно обычной роли приложения, не против владельца инфраструктуры.
- Сбор контекста других участников отключён. Тексты тестируемого участника, включая исключённые сообщения, могут передаваться выбранному LLM как ограниченный по размеру материал для анализа. Сообщения и результаты хранятся до принятия оператором политики удаления. Сообщите участникам о хранении/провайдере до использования.
- Персональные launch-сессии действуют до 1 часа; это не токен на один HTTP-вызов. В БД индексируется SHA-256; исходная ссылка также есть в защищённом payload исходящего сообщения. Старые записи токенов очищаются спустя сутки после истечения, update IDs — через 7 дней.
- Схема содержит персональные идентификаторы. Не публикуйте дампы, screenshots таблиц и payload outbox. Не подключайте service_role/пароль PostgreSQL к браузеру.

## Почему команды не появились

1. Выполните `npm run setup` с PUBLIC_URL и WEBHOOK_SECRET в локальном `.dev.vars`.
2. Проверьте `/readyz`: 503 означает проблему окружения, подключения или миграции.
3. В логах `telegram_setup_failed` — проверьте токен, совпадение username, URL и исходящий доступ Telegram.
4. Перезапустите Telegram-клиент. Команды зарегистрированы в default scope; отдельные legacy scope/language настройки могут их перекрывать.
5. При автоматическом запуске ждите распространения Cron до 15 минут. Отдельный `/setcommands` не нужен.

## Почему бот молчит

- `ALLOWED_CHAT_IDS` должен содержать фактический ID; после преобразования обычной группы в supergroup ID меняется. Старые калибровки не переносятся автоматически на новый ID.
- Проверяйте `PUBLIC_URL`, наличие webhook и остановку старого polling-процесса.
- Команды старше 15 секунд не запускают новую попытку — бот предлагает повторить.
- Посмотрите очередь из SQL Editor:

```sql
SELECT kind, status, attempts, next_run, last_error
FROM titsbot.outbox
WHERE status = 'PENDING'
ORDER BY next_run
LIMIT 30;
```

## Mini App показывает ошибку авторизации

Откройте свежую персональную кнопку `/getdmt` тем же аккаунтом. Обычный браузер не передаёт подписанный initData. Ссылка чужого пользователя и ссылка старше часа отвергаются. В BotFather должен быть включён **Main Mini App** с адресом Worker.

## ANALYZING не заканчивается

Проверьте LLM_BASE_URL, LLM_MODEL, ключ, баланс и поддержку strict json_schema. Сервис не заменяет ошибку LLM выдуманной оценкой; анализ повторится по backoff. Raw ответ и hash анализа сохраняются только после проверки схемы.

## Тег PENDING

Бот должен быть администратором с `can_manage_tags`, а участник — обычным членом группы. Назначение не понижает администраторов, не выдаёт права и не меняет permissions. При возврате участника в группу тег восстанавливается. Успешное назначение также сверяется примерно раз в час.

## Локальная разработка

Используйте отдельного тестового Telegram-бота и PostgreSQL. Примените миграцию в чистую локальную БД, создайте `.dev.vars` на основе примера и укажите DATABASE_URL. Для локального Hyperdrive Wrangler может потребоваться переменная `CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE` с тем же локальным DSN. Не направляйте dev/prod к одной базе с разными секретами и конфигурациями.

`npm run dev` запускает Worker, но Telegram не доставляет webhook на localhost. Для end-to-end удобнее отдельный test Worker с HTTPS, отдельной БД и ботом. Не включайте удалённое тестирование на production-секретах без понимания побочных эффектов.

## CI и развёртывание

CI требует `npm install`, поскольку lockfile не генерировался в офлайн-среде подготовки. После фиксации package-lock.json переключите install в workflow на `npm ci`. CI использует отдельную PostgreSQL service; интеграционный тест откажется запускаться, если схема titsbot уже существует.

Перед production убедитесь, что CI зелёный. Wrangler dry-run не проверяет действительность Hyperdrive ID, наличие secrets, права Telegram или оплату LLM. Проверяйте production по разделу 9 README.

Обновления конфигурации `config.json` применяются только к новым пользователям: snapshot существующего пользователя неизменяемый. В этой версии UI поддерживает фиксированные 60 секунд Chat и 3×30 секунд MT; изменение протокольных констант требует согласованного обновления клиента/сервера и миграции версии, а не только редактирования JSON.
